# 연구 질문 재정의 (Formulation)

같은 목표를 서로 다른 연구 질문으로 표현한 뒤 가설을 만든다. 바꾸는 것은 탐색 관점이며, 사용자의 목표·평가 기준·고정 제약은 유지한다. 이 문서는 Pi Workbench가 작성한 경량 절차다.

## 적용할 때

- 사용자가 새로운 연구 방향, 정체된 접근의 대안, 또는 연구 문제의 재정의를 요청했다면 가설 생성 전에 한 번 적용한다.
- 논문 요약·번역, 정해진 분석·검정력 계산, 확정된 가설의 구현·실험 수행·원고 교정에는 적용하지 않는다. 명시적으로 재정의도 요청했다면 그 부분에만 적용한다.
- 같은 목표와 제약으로 이미 만든 formulation이 있으면 재사용한다. 조건이 바뀌었을 때만 관련 항목을 갱신하고 변경 이유를 남긴다.
- 사용자가 방법을 고정했으면 그 안에서 질문을 달리한다. 바꿀 수 있는 관점이 하나뿐이면 그대로 진행하며 후보 수를 채우지 않는다. 적용하지 않는 요청에 별도 재정의 보고서를 붙이지 않는다.

## 1. 목표와 제약 고정

기존 요청·자료에서 다음을 짧게 추출한다. 이미 받은 정보를 다시 질문하지 말고, 결과를 바꿀 미확인 조건만 질문하거나 `TBD`로 남긴다.

| 구분 | 기록할 내용 |
|---|---|
| 목표 | 해결하려는 문제와 성공했을 때 달라지는 결과 |
| 평가 계약 | 지표·목표값·평가 단위·운영점·비교 기준·평가 데이터 경계 중 정해진 항목 |
| 고정 조건 | 사용자가 확정한 방법, 자원, 시간, 데이터, 호환성, 제외 범위 |
| 가정과 자유도 | 잠정 가정, 변경 가능한 방법, 아직 모르는 조건 및 출처 |

정해지지 않은 수치·예산·표본 수를 만들지 않는다. 잠정 가정을 고정 제약으로 승격하지 않고, 고정 제약을 자유도로 바꾸지 않는다. 대리 지표나 다른 평가 단위를 추가로 살펴볼 수는 있으나 원래 합격 기준을 대체하지 않는다. 범위 밖의 방향은 제약 변경이 필요한 제안으로 따로 표시하며 현재 조건을 충족한 후보로 세지 않는다.

## 2. 해결책보다 질문을 먼저 생성

아직 선호하는 해결책이나 대표 가설을 정하지 않은 상태에서, 아래 관점 중 문제에 맞는 것만 사용해 한 차례 질문을 만든다. 보통 3–5개 이내면 충분하며, 의미 있는 차이가 적으면 더 적게 쓴다. 이는 운용상 가이드이며 최소 개수나 논문의 재현 조건이 아니다.

- **규모·경계:** 개별 관측, 구성 요소, 전체 시스템, 시간·환경 조건 중 어디를 보면 다른 병목을 찾을 수 있는가?
- **메커니즘·병목:** 같은 결과를 만들 수 있는 서로 다른 과정은 무엇이며, 어느 관측으로 구분할 수 있는가?
- **측정·증거 공백:** 현재 관측이 구분하지 못하는 설명은 무엇인가? 확인된 불일치나 자료의 한계는 어디에 있는가?

각 항목을 답할 수 있는 질문으로 쓴다. 모델명·알고리즘·도구를 나열한 해결책 목록이나 같은 질문의 표현 변경은 새로운 formulation이 아니다. 프레임마다 다른 정보·메커니즘·판별 관찰이 필요한지 확인한다. 필요하면 인접 분야의 개념으로 질문을 표현하되, 이 단계에서 광범위한 타 분야 검색이나 구성 요소 조합을 의무화하지 않는다.

이미 확인한 관찰과 자료를 이용하고, 새 해석은 가정으로 표시한다. 문헌의 공백·모순·신규성에 관한 주장은 실제 검색 범위와 출처가 있을 때만 쓴다. 검색하지 않았다면 `확인 필요`로 남기며, 검색 결과가 없다는 이유만으로 미개척 분야라고 단정하지 않는다.

## 3. 목표 정합성과 질문 간 차이 확인

각 질문이 원래 목표에 어떻게 기여하며 고정 조건을 지키는지 확인한다. 필요한 근거와 판별 관찰이 같은 항목은 묶되 원래 ID를 남긴다. 반대로 가정·조건·예측이 다르면 표현이 비슷해도 보존한다. 남은 질문이 하나여도 실패가 아니다.

출력은 고정 목표·제약 요약과 다음 표면 충분하다. 새 파일이나 장문 계획은 요청된 경우에만 만든다.

| ID | 재정의한 연구 질문 | 달라지는 탐색 범위·병목 | 목표·고정 조건과의 연결 | 필요한 증거·판별 관찰 |
|---|---|---|---|---|
| F1 | 확인할 관계나 설명을 질문으로 작성 | 다른 프레임과 실질적으로 다른 점 | 보존한 조건 및 정합성 | 관측·자료와 미확인 사항 |

이 표는 연구 방향을 검토하기 위한 자료다. 질문의 다양성을 과학적 타당성이나 가설의 참일 확률로 해석하지 않는다. 점수로 자동 우승 가설을 정하거나 실험 채택을 선언하지 않는다.

## 4. 요청한 후속 작업으로 연결

- **재정의만 요청:** 표와 핵심 미확인 사항으로 마친다.
- **아이디어·가설도 요청:** 기존 `scientific-brainstorming` 또는 `hypothesis-generation`으로 이어간다. 각 가설에 formulation ID, 원래 목표·제약, 근거 상태, 판별 예측·기각 조건을 전달한다. 연결 관계를 유지하고 기존 스킬의 독립 발상·반론 검토를 불필요하게 반복하지 않는다.
- **실험 설계도 요청:** 기존 `experimental-design` 등 필요한 스킬로 이어간다. 실험 실행은 현재 요청에 포함된 범위에서만 한다. 아이디어 생성만으로 반복 실행·학습·유료 서비스 사용을 시작하지 않는다.

이미 Pi Orche의 MDSD 같은 탐색 기능이 실행 중이면 그 결과에 이 질문·제약 정보를 연결한다. 이 절차를 읽었다는 이유로 모드를 바꾸거나 추가 에이전트·별도 연구 루프를 만들지 않는다.

## 짧은 예시

가상 요청: “영상 기반 검사에서 재현율·정밀도 기준과 검수량 한도를 유지하면서 새로운 후보 생성 방향을 찾아라. 특징 추출기는 고정한다.”

- F1: 어떤 관측 조건에서 정상 구조와 결함의 구별 정보가 부족해지는가?
- F2: 후보의 누락·중복·경계 오차 중 어느 과정이 고정 운영점의 성능을 제한하는가?
- F3: 제품·시간대별 오류 차이가 특징의 한계와 측정·라벨 불일치 중 무엇으로 설명되는가?

각 질문에는 서로 다른 오류 자료와 판별 관찰이 필요하다. 특징 추출기 교체, 기준 완화, 평가 데이터 재튜닝을 조건을 충족한 해결책으로 넣지 않는다. 수치가 주어지지 않았으므로 임의 목표값도 만들지 않는다. 이 예시는 형식 설명이며 실제 연구 결과가 아니다.

## 근거와 적용 범위

[Abelio 논문 v1](https://arxiv.org/html/2611.22988v1)의 §4.2–4.3은 목표·제약을 정하고 해결책 전에 서로 다른 문제 표현을 만드는 절차를 설명한다. §2.3·4.9의 제거 실험은 전체 파이프라인에서 이 단계와 가설 다양성의 관계를 평가한다. 이 경량 지침의 효과나 현재 사용하는 모델 대비 개선율은 아직 측정하지 않았다.

Workbench는 질문 재정의 원칙만 참고한다. 원본 코드·프롬프트를 복사하거나 번들링하지 않으며, Latent Selector·임베딩 서버·Element Selection·반복 토론은 이 단계에 포함하지 않는다. 기존 스킬을 대체하지 않고 목표·제약을 보존하는 앞단 절차로 연결한다.
