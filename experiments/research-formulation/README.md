# Research Formulation 1단계 평가 계획

**상태: 계획과 합성 요청만 준비됨. A/B 측정 미실행.** 이 문서는 유료 모델 호출, 반복 작업 또는 배포를 시작하지 않는다. `experiments/`는 npm 배포 대상이 아니다.

## 비교 목적과 변형

같은 목표와 제약 아래, **가설 생성 전에 문제를 다른 연구 질문으로 구성하는 단계**가 실현 가능하고 서로 다른 후보를 늘리는지 확인한다. 기준선에도 독립 발상·구조적 군집화·반론 검토가 있으므로, 이를 새 기능의 효과로 계산하지 않는다.

| 변형 | 고정할 내용 |
|---|---|
| A | 변경 전 `2fe50ad98b9d7e546be45a6589a07543b95076e2`의 Workbench 전체 트리 |
| B | A에 Formulation 1단계 지침과 연결만 추가한 트리. 실제 실행 전에 commit 또는 파일 목록·SHA-256을 기록 |

Embedding 선택기, 외부 문헌 요소 탐색, 토론 에이전트, 모델 교체를 동시에 바꾸지 않는다. A와 B는 동일한 연구 프로필, 모델 버전·effort, 도구, 입력 자료, 최종 후보 상한, 출력 양식 및 총 실행 한도를 사용한다. A에서도 기존 가설·브레인스토밍 스킬을 사용할 수 있어야 한다.

이 계획의 주 비교는 **`research` 프로필을 명시한 조건의 산출물 품질**이다. `auto`의 프로필 발견률이나 one-shot 경로의 도달 여부는 별도 검증으로 기록하고 이 품질 비교와 합치지 않는다.

## 요청과 노출 관리

[requests.json](requests.json)은 `id`, `prompt`만 가진 20개 합성 요청이다. 사용자 자료나 실제 실험 결과를 포함하지 않는다. 아래 기대 동작과 채점 기준은 실행 에이전트에 전달하지 않는다. 에이전트에는 해당 요청 하나, 해당 변형, 공통 출력 지침과 허용 자료만 보인다. 형제 실행의 결과와 이전 피드백도 공유하지 않는다.

| 요청 ID | 기대 동작 | 놓치면 안 되는 조건 |
|---|---|---|
| surface-inspection | 탐색 | 기존 검출기, 라벨 200장, 제품 단위, 오탐률 2% 이하 |
| demand-forecasting | 탐색 | 고정 모델 계열, 미래 정보 제외, 개점일 기준 매장 분할, MAE |
| battery-estimation | 탐색 | 공개 로그만, 개체 분할, 온도별 오차 |

| synthetic-curriculum | 탐색 | 모델·학습 토큰 고정, 평가 문제 및 변형 누수 금지 |

| abstract-summary | 원래 작업 수행 | 제공된 가상 초록을 세 문장으로 요약 |

12개 탐색 요청과 8개 반대 사례는 모두 **공개 개발용 자료**다. 이 자료로 지침을 수정하거나 시연한 뒤 독립 holdout이라고 부르지 않는다. 확증 비교에는 지침 작성에 참여하지 않은 평가자가 새 요청·기준을 만들고, 두 변형과 분석 계획을 먼저 고정해야 한다.

## 실행 전 고정할 항목

1. A/B 트리 digest, 요청 파일 digest, 모델 식별자·버전·effort, 호스트 버전, 도구 및 공통 지침을 기록한다.
2. 요청당 반복 수, 짝지은 실행 순서를 결정할 seed, 전체 비용 상한과 시간 한도를 **결과를 보기 전에** 정한다. 값이 정해지기 전에는 실행하지 않는다. 예산을 초과하면 중단 상태로 남긴다.
3. 각 요청·반복에 A/B를 짝짓고 순서를 무작위로 교차한다. 새 세션에서 실행하며 한 변형의 산출물을 다른 변형의 입력으로 쓰지 않는다.
4. 주 비교는 제공된 자료와 동결한 공통 근거 묶음만 사용한다. 외부 검색이 필요한 별도 비교는 같은 검색 도구·상한·조회 시점 조건을 주고 결과를 전부 보존한다. 이를 주 비교와 섞지 않는다.
5. 공통 출력 지침은 아래처럼 두 변형에 똑같이 전달한다. 문제 재정의를 직접 요구하는 지침은 A에 추가하지 않는다.

> 원래 요청의 범위와 형식을 따르세요. 연구 방향을 제시하는 요청이면 최종 후보를 최대 3개로 제한하고, 각 후보의 가설·작동 원리·근거와 가정·판별 관찰 또는 최소 검증·제약 충족 여부를 간결하게 적으세요. 적합한 후보가 부족하면 억지로 채우지 마세요. 그 밖의 요청은 요청된 산출물만 작성하세요.

Formulation 과정은 추적 기록으로 보존하되 품질 판정에는 두 변형의 동일 양식 최종 후보를 사용한다. 요약 모델을 추가해 품질 차이를 바꾸지 않는다. 최종 후보 수를 맞춘다는 이유로 부적합 후보를 보충하거나 성공한 실행만 남기지 않는다.

## 판정과 기록

### 1. 적용 범위와 목표 보존

- 탐색 요청: B가 **해결책을 제시하기 전에** 서로 다른 연구 질문을 구성했는지 확인한다. 알고리즘 이름만 바꾼 목록이나 같은 질문의 말바꿈은 다른 formulation으로 세지 않는다.
- 차이는 바뀌는 관찰 단위·메커니즘·찾아야 할 자료·판별 관찰로 설명할 수 있어야 한다. 관점 수를 채우기 위해 제약을 위반하면 실패다.
- 반대 사례: Formulation이나 새 연구 계획을 덧붙이지 않고 원래 계산·요약·구현을 완료했는지 본다. Formulation 문서를 읽었다는 사실만으로 오작동이라 판정하지 않는다.
- 목표 수치·지표·평가 단위·운영점·고정 방법을 바꾸거나, 미정인 목표값을 합의된 값처럼 만들거나, 수행하지 않은 검색·실험을 주장한 경우를 각각 별도로 기록한다. 평균 점수로 상쇄하지 않는다.

### 2. 최종 후보의 유효성과 차별성

변형명을 가리고 무작위 순서로 두 평가자가 판단한다. 작성 에이전트와 별개의 평가자를 사용하고, 사람 검토인지 LLM 검토인지 밝힌다. 의견 불일치는 양쪽 판단과 조정 이유를 남긴다.

후보는 원래 목표·제약을 충족하고, 가설과 관찰 사실을 구분하며, 가능한 판별 관찰과 다음 검증이 있어야 유효하다. 실제 실험 성공이나 과학적 참을 뜻하지 않는다. 같은 메커니즘과 판별 관찰을 공유하는 표현 변형은 한 후보로 묶되 원래 ID와 묶은 이유를 보존한다.

**주 지표:** 탐색 요청당 유효한 고유 후보 수(0–3). 함께 보고할 지표는 목표·제약 위반 수, 반대 사례의 원래 작업 완료율과 불필요한 확장률, 판별 검증의 구체성, 근거 없는 주장 수다. 문헌과 멀다는 이유만으로 새로움이나 타당성을 인정하지 않는다.

### 3. 효율과 실패

모든 단계의 입력·캐시 읽기·캐시 쓰기·출력 토큰, 요청 수, 경과 시간, 비용과 산정 근거를 보존한다. 초기 재정의, 검색, 재시도와 실패도 포함한다. 비용이 없으면 `unknown`이며 0으로 간주하지 않는다. 후보가 0개인 실행의 후보당 비용은 미정으로 남기고, 집계에서는 전체 비용과 전체 유효 후보 수를 같이 보고한다. 예산 중단·도구 실패·거부·불완전 출력은 누락하지 않고 사유별로 분리한다.

최소 실행 기록: `requestId`, `repeat`, `arm`, `treeDigest`, `model`, `effort`, `inputDigest`, `sourceDigest`, `order`, `startedAt`, `durationMs`, `usage`, `cost`, `status`, `finalText`, `tracePath`, `review`.

## 분석과 다음 단계

같은 요청의 A/B 차이를 먼저 계산하고 반복은 요청 안에서 집계한다. 후보 하나나 반복 하나를 독립 연구 문제로 세지 않는다. 탐색 요청과 반대 사례는 분리 보고하며, 불확실성은 요청 단위의 짝지은 재표집 등으로 제시한다. 20개 합성 개발 요청의 결과는 현장 연구 생산성이나 ML 정확도 개선율로 일반화하지 않는다.

목표·제약을 훼손한 사례는 원인을 해결한 뒤 새 변형으로 다시 평가한다. 유효 후보 수 증가와 비용·지연·오발동의 상충 관계를 함께 보고한다. 효과 크기와 허용 회귀 폭은 예비 결과로 판단할 수 있지만, 이를 이미 본 개발 세트에 소급해 확증 합격선으로 쓰지 않는다. **현재는 개선율·합격 판정·채택 효과가 없다.** 다음 단계의 선택기나 반복 토론 추가는 이 1단계의 결과와 별개의 실험으로 다룬다.
